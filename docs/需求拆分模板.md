# 需求拆分模板

> 用法：复制本文件到 `docs/requirements/<需求名>.md` 后填写；节标题不要改（脚本/统计按标题解析）。
> 示例见 `docs/requirements/示例-薪资包管理查询.md`。
> 产物定位：**阶段 1 的唯一交付物**，评审通过后才进入用例设计（见 `../AGENTS.md` 阶段 1/2）。

## 4. 测试点清单

> 一个测试点 = 一个可验证的断言方向；粒度比用例粗、比规则细。

| 测试点ID | 测试点 | 覆盖规则 | 层级 | 优先级 | 是否做 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| TP-01 | | R1 | 接口 / UI / 不可自动化 | P0 | ✅/❌ | 不做的写原因 |
| TP-02 | | | | | | |

层级判定口径：
- **接口**：后端逻辑、参数校验、落库结果、状态流转、权限
- **UI**：页面呈现、交互流程、前端校验提示、列表/详情字段
- **不可自动化**：需人工判断的视觉/体验项（写清楚谁验、怎么验）

## 6. 不做的场景（一定要写）

| 场景 | 不做的原因 |
| --- | --- |
| 例：非法枚举/空必填等脏数据 | 公司口径：前端有拦截即可，接口健壮性不测 |
| 例：某国家未配置国家模板 | 环境未配置，产品明确不做 |

## 7. 影响面 / 回归范围

| 项 | 内容 |
| --- | --- |
| 改动接口 | 如 `POST /api/center/payrollSalaryPackage/list`（列出便于匹配历史用例） |
