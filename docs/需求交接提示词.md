# 需求交接提示词（复制粘贴给 AI 用）

用途：把一个新需求交给 `D:\lu\pycharm\autotest` 里的 AI 自动化助手，让它按 `AGENTS.md` 六阶段流程跑完
「需求拆分 → 用例 → lint → 执行 → 失败分析 → 禅道草稿」。

> 使用前只需替换 `【】` 里的内容；没有的信息就写「待确认」，不要删掉小块。
> 前提：`.env` 的 `ACCESS_TOKEN_ADMIN` 新鲜（约 2 小时过期，过期就自己复制一次浏览器 `GSR-Token`）。

---

## 一、标准版（推荐，接口 + UI 双轨）

```text
先读 autotest/AGENTS.md（重点 §0.2 交接状态与能力边界）和 autotest/PROMPT_bug_filing.md，
然后按 AGENTS.md 的六阶段流程做下面这个需求。

【第 0 步：接手自检】
在 D:\lu\pycharm\autotest 下依次执行，把结果贴给我：
  python run.py --list
  python run.py lint
  python run.py check-token
  python run.py api 薪资包管理查询
任一条不过就停下来说明原因（token 过期就让我更新 .env，不要自己猜代码问题）。

【需求】
- 需求名：【例如：薪资包按员工导出算薪明细】
- 材料：【PRD 路径 / 禅道需求号 / 截图路径 / 直接粘贴的正文】
- 归属项目：【Payroll&结算 / 假勤 / 报销 / 其它】
- 涉及页面与接口：【已知的就写，不明确就写"待你从材料里提取"】
- 环境与数据：【测试环境；客户 528；供应商 107；其它固定数据写在这里】
- 验收侧重：【接口数据正确 / 页面呈现 / 双层都验】
- 是否允许写库：【不允许 / 允许（我会在阶段 1 确认具体 SQL）】

【执行要求】
1. 阶段 1 只做分析和拆解：产出 docs/requirements/<需求名>.md，套 docs/需求拆分模板.md，
   必须有规则矩阵（R1、R2…）、测试点清单（每条挂到规则上）、不做的场景及原因。
   然后把「测试点清单 + 不做的场景」列给我确认，我说"可以"再往下走。
2. 阶段 2 写用例：接口用 api/testcase/test_<主题>.xlsx（复制 test_TEMPLATE_api.xlsx），
   UI 用 ui/testcases/<项目>/<名>.yaml（参考 _TEMPLATE_ui_case.yaml + 现有定位器），
   写好注册表项。场景 / 场景说明两列必填，断言要验业务字段不要只验 code=200。
3. 阶段 3 跑 python run.py lint，ERROR 必须为 0 才允许执行；警告读一眼并说明哪些不阻塞。
4. 阶段 4 执行：python run.py api <项目名> / python run.py ui <项目名> --headless。
   比 120 秒长的命令用后台跑 + 轮询 reports/run_out.txt。
5. 阶段 5 对每条失败判定「产品缺陷 / 用例或数据问题 / 环境问题」，附证据
   （reports/evidence/*.json、接口返回原文、截图），拿不准就重跑一次再说结论。
6. 阶段 6 只出提单草稿（python run.py zentao），把草稿和「按规则不提」清单一起给我，
   我确认后才允许 --submit --yes。
7. 结束时按 AGENTS.md §9 汇报模板回：范围/覆盖、用例条数与 lint、执行统计、失败判定、提单、待确认。

【红线，违反即返工】
- 只改 autotest/；D:\lu\pycharm\api 和 ui_playwright 只读。
- 任何写库（insert/update/delete/DDL）必须在我确认后执行，禁止无 where 的全表操作。
- 不要自己提交缺陷、不要自己删除禅道单据。
- 环境/权限类失败只报告（附错误码），不许改断言去迁就环境。
- 用例数据要唯一化，造的数据必须清理，跑完自检无残留。
```

## 二、变体：只做接口

把标准版的「涉及页面与接口」改成只需接口，并在执行要求里删掉 UI 相关段落，补一行：

```text
只用接口层验证（不做 UI）：页面呈现类的测试点标记为「不在本次范围」并写原因。
```

## 三、变体：只做 UI

```text
只用 UI 层验证（接口只用来核对数据）：先跑 tools/ui_capture.py 采集定位器再写用例；
detail 元素名必须已存在于 ui/config/locators/<项目>.yaml，不许写"猜"的选择器。
```

## 四、变体：不加新用例，只回归

```text
本次不新增用例，只做回归：
  python run.py api 【项目名】
  python run.py ui  【项目名】 --headless
跑完按 AGENTS.md §9 汇报；失败按阶段 5 判定，只对「断言失败 + 历史失败 ≥2 次」的用例出提单草稿。
```

## 五、AI 大概率会回来问你的 5 件事（提前想好答案更顺）

1. **token 过期** → 你在浏览器登录后复制 `GSR-Token` 填进 `.env` 的 `ACCESS_TOKEN_ADMIN`。
2. **需求里有口径不清的点** → 让它先按"待确认"写进需求文档继续推进，不要停工等（公司口径：多提、允许噪音）。
3. **要不要写库** → 阶段 1 会给「表 / SQL / 影响行数 / 恢复方案」，确认才写。
4. **用例条数与范围** → 阶段 1 的测试点清单就是范围基线，砍/加都在这一步说。
5. **提单** → 草稿里重点看：模块（payroll 393 / 假勤 392）、期望/实际是否是人话、接口单无截图 / UI 单有截图。
