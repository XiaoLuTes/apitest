# 项目资料库（按项目分层）

测试过程中会用到的**原始资料**放这里，按「项目 → 资料类型」分层。AI 拆需求、写用例、查表结构时先读对应目录索引。

```
docs/项目资料/
├─ payroll/                    # 算薪、薪资包、结算包、收款包…
│   ├─ 接口文档/               # OpenAPI/Swagger 导出、接口说明 md、抓包整理
│   ├─ 数据库表结构/           # 建表语句、SHOW CREATE TABLE 导出、字段说明
│   ├─ 需求文档/               # PRD、原型、评审纪要
│   └─ 测试数据/               # 原始导出（客户/员工/单据 xlsx、sql、截图）
└─ 假勤/                       # 请假、加班、销假、审批链…
    └─ （同上四类）
```

## 放资料的三条约定

1. **文件名**：`YYYYMMDD-来源-主题.扩展名`，例：`20261113-禅道导出-薪资包列表接口.md`、`20261113-数据库导出-gsr_payroll_salary_package.sql`。
   同一份资料更新时保留日期，不覆盖旧文件（便于回溯"当时按哪版需求写的用例"）。
2. **敏感信息**：不要放账号密码、token、真实客户隐私数据；连接信息统一写在根目录 `.env`，这里只写"用哪个账号/哪套数据"的说明。
3. **新项目**：直接建 `docs/项目资料/<项目名>/` 四个子目录 + 一个 `README.md` 索引，再在下面「项目清单」登记一行。

## AI 使用约定（写给执行者）

- 拆需求前：读 `docs/项目资料/<项目>/需求文档/` 里最新一版 PRD；没有就向用户要。
- 写接口用例前：读 `接口文档/` 确认路径/参数/返回字段；没有就以「实测抓包」为准并回填到该目录。
- 写 DB 校验前：读 `数据库表结构/` 确认表名与主键（注意 `gsr_approval_users` 主键是 `gsr_approval_users_id`，不是 `id`）。
- 造数/取数前：读根目录 `测试数据.md`，优先复用已登记的数据集，不要每次重新找。
- 新增资料后：在对应 `README.md` 的「已收录清单」里补一行（日期 / 文件 / 用途）。
