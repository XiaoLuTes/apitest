## 2. 对账中心典型查询链路（实测整理）

财务收款 → 客户结算包 → 对账包 → 算薪任务节点，四张表串起来：

```sql
-- 1) 财务收款主单
SELECT * FROM gsr_settlement_financing_proceeds
WHERE settlement_financing_proceeds_id = 5860;

-- 2) 收款单 → 客户结算包 → 对账包（拿对账单文件路径）
SELECT scp.settlement_client_package_id,
       scp.settlement_financing_proceeds_id,
       scp.gsr_payroll_reconciliation_package_id,
       rp.statement_file_path,
       rp.reconciliation_data_source
FROM gsr_settlement_client_package scp
JOIN gsr_payroll_reconciliation_package rp
  ON rp.gsr_payroll_reconciliation_package_id = scp.gsr_payroll_reconciliation_package_id
WHERE scp.settlement_financing_proceeds_id = 5860;

-- 3) 对账包在算薪任务「结算」节点的状态（task_node='3'）
SELECT pctr.gsr_payroll_reconciliation_package_id,
       pctr.task_node, pctr.st_status, pctr.update_by, pctr.update_time
FROM gsr_payroll_client_task_record pctr
JOIN gsr_settlement_client_package scp
  ON scp.gsr_payroll_reconciliation_package_id = pctr.gsr_payroll_reconciliation_package_id
WHERE scp.settlement_financing_proceeds_id = 5860
  AND pctr.task_node = '3'
ORDER BY pctr.update_time DESC;
```

关系总结（写断言时按这个定位字段）：

```
gsr_settlement_financing_proceeds   财务收款主单
        ↓ settlement_financing_proceeds_id
gsr_settlement_client_package       客户结算包（连结算包与对账包）
        ↓ gsr_payroll_reconciliation_package_id
gsr_payroll_reconciliation_package  对账包（statement_file_path 对账单文件）
        ↓ gsr_payroll_reconciliation_package_id
gsr_payroll_client_task_record      算薪任务节点记录（st_status 状态 / update_by / update_time）
```

对应 `reconciliationPackageItemList` 里一条数据的取值位置：

| 字段 | 位置 |
| --- | --- |
| 文件路径 | `gsr_payroll_reconciliation_package.statement_file_path` |
| 包 ID | `gsr_payroll_reconciliation_package.gsr_payroll_reconciliation_package_id` |
| 状态 | `gsr_payroll_client_task_record.st_status` |
| 更新人 / 时间 | `gsr_payroll_client_task_record.update_by` / `update_time` |

## 3. 写 `db_select` 的注意事项

1. **主键名不等于表名 + `_id`**：`gsr_payroll_salary_package` 的主键是 `payroll_salary_package_id`（少了 `gsr_` 前缀），
   `gsr_employee_leave_info` 的主键甚至是 `gsr_employee_info_id`（在假勤库里）。
2. **金额字段多位 `decimal`**，断言时注意精度（比较用 `count:`/数值比较而不是字符串相等）。
3. **软删除**：`del_flag`（0 存在 / 2 删除）、`data_flag` 等标志位存在时，查询要带上过滤条件，否则会查到期数据。
4. **一个单据可能有多条历史**：状态类字段（`st_status`、`task_node`）取 `ORDER BY update_time DESC LIMIT 1` 再断言。
5. **`db_select` 只看"当前落库状态"**：异步流程（导入/结算/审批）断言前先确认任务已到终态，否则会误判。
