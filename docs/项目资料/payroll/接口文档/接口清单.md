# payroll 接口清单

> **来源与可信度**：`✅实测` = 我们跑通并验证过；`📄整理` = 来自桌面 `20261113-桌面-payroll接口整理.md`（你手工整理，未逐条复跑）；`⚠️待确认` = 见过但未复核。
> **鉴权**：管理端 `Authorization: Bearer ${access_token_admin}`；员工端 `${user_token}`（见 `.env`）。
> **通用返回**：`{code, msg, data}`，列表类为 `{total, rows}`；`code=200` 为成功。
> **异步接口**：先拿 `taskKey`，再轮询 `/api/file/asyncDownload/status`，成功后才可下载。

## 0. 通用约定

### 错误码（实测）

| code | 含义 | 备注 |
| --- | --- | --- |
| 200 | 成功 | 部分接口失败也返回 200 + `msg`（如 402 导入校验用例） |
| 100100 | 参数错误 | 空/非法参数 |
| 110106 | 没有访问权限 | 权限缓存/角色未同步时常见，换 `.env` 的 `ACCESS_TOKEN_ADMIN` 重试 |
| 100007 | 版本冲突 | 员工标签类接口 |
| 110198 | 作废缺参 | 作废薪资包未传说明 |
| 110215 | 数据不存在 | 传了不存在的 ID |

### 状态与类型取值

| 字段 | 取值 |
| --- | --- |
| `payPayType` / `payPagType` | `1` = ON_CYCLE，`2` = OFF_CYCLE ⚠️待确认 |
| `payrollStatus` | `0` = 待发起算薪；导入确认后 `payroll_status=2` ✅实测 |
| 结算包 `tag` | `2` = 待业务审核，`5` = 待财务审核（该环境跳过 3）✅实测 |
| `sourceSystem` | `0` = 系统创建，`1` = 手动创建，`2` = RPA 创建 ✅（表注释） |

## 1. 薪资包

| 用途 | 方法 | 路径 | 关键入参 | 关键返回 / 备注 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 列表 / 按条件查询 | GET | `/api/center/payrollSalaryPackage/list` | `pageSize`、`pageNum`、`payrollSalaryPackageCode`、`settlementPackageCode`、`payPagType`、`supplierId`、`country`、`payrollStatus` | `{total, rows:[...]}`；行内字段见下「薪资包字段」 | ✅实测 |
| 薪资包详情 | GET | `/api/center/payrollSalaryPackage/{id}` | 路径参数 = `payrollSalaryPackageId` | 返回单个薪资包对象 | 📄整理 |
| 薪资包薪资项 | POST | `/api/center/payrollSalaryPackage/viewPayrollSalaryItem` | `{payrollSalaryPackageId, exportTypeList:["1"]}` | `exportTypeList`：1 固定薪酬、2 薪酬调整、3 随薪报销、4 一次性变动、5 假勤加班、6 考勤报表、7 国家日历 | 📄整理 |
| 包内薪资单 | GET | `/api/center/payrollSalaryPackage/queryPayrollSalaryList` | `payrollSalaryPackageId`、`pageSize`、`pageNum` | 分页薪资单列表 | 📄整理 |
| 创建薪资包 | POST | `/api/center/payrollSalaryPackage/add` | `supplierId`、`serviceMonth`、`payPagType`、`payrollSalaryList`… | **只返 code/msg，不返 ID**，要用 list 反查；缺 `payrollSalaryList` 仍 200 并建 0 人空包（疑缺陷） | ✅实测 |
| 作废薪资包 | PUT | `/api/center/payrollSalaryPackage/packageVoided` | `{voidingExplanation, payrollSalaryPackageId}` | 需 `remove` 权限；已作废再作废仍 200（幂等） | ✅实测 |
| 薪资包规则列表 | GET | `/api/center/payrollSalaryPackageRule/list` | `pageSize`、`pageNum` | 同角色下该接口权限正常，可用于权限对比 | ✅实测 |

### 薪资包行字段（list 返回，实测）

| 字段 | 含义 |
| --- | --- |
| `payrollSalaryPackageId` | 薪资包主键（**会变，按 code 查，别写死**） |
| `payrollSalaryPackageCode` | 薪资包编码，如 `SAL-20261112-0001` |
| `payPayType` | 1=ON_CYCLE |
| `supplierId` / `supplierName` | 供应商（如 107 / Lucas专用供应商） |
| `country` | 国家（如 Canada / France） |
| `serviceMonth` | 服务月份，`202611` |
| `payrollStatus` | 0=待发起算薪 |
| `employeeCount` | 员工人数 |
| `lockTime` | 算薪日（锁定时间） |
| `sourceSystem` | 0=系统创建 |
| `settlementPackageCode` | 结算包编码（未生成时 null） |

## 2. 国家模板与文件（异步下载链路）

| 用途 | 方法 | 路径 | 关键入参 | 备注 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 下载国家模板 | GET | `/api/center/payrollSalaryPackage/exportPayrollSalaryTemplate` | `payrollSalaryPackageId` | **副作用：后端会根据当前薪资包生成结算包**；返回 `taskKey` | 📄整理 |
| 查生成状态 | GET | `/api/file/asyncDownload/status` | `taskKey` | 返回 `{status:"SUCCESS", progress:100, fileName:"SPP..._国家模板.xlsx"}`；建议 `retry` 轮询 | 📄整理 |
| 下载文件 | GET | `/api/file/asyncDownload/download` | `taskKey` | 状态 SUCCESS 后再调 | 📄整理 |
| 上传文件 | POST | `/api/center/file/centerUploadFiles/100049` | 二进制文件（multipart） | 返回可用路径 `center/settlementDistrict/packageDataPath/...`，供 `importPayroll` 用 | 📄整理 |

> 框架侧：`download` 动作只支持 GET；上传类接口目前用 POST + `data` 传路径，multipart 需要扩展动作（见待补）。

## 3. 导入与结算

### 3.1 导入薪资结果

```
POST /api/payrollCalculation/payrollCollect/importPayroll
{
  "payrollSalaryPackageId": 2501,
  "payrollResultFilesUrls": ["center/settlementDistrict/packageDataPath/2026/11/13/SPP..._20261113113719A502.xlsx"],
  "payslipFiles": [], "otherFilesUrls": [], "bankFilesUrls": []
}
```
返回 `data.x` / `data.y` / `data.importIssues` 是「导入校验」的断言依据 ✅实测（402 用例即断言这三处）。

### 3.2 确认发起结算（confirmImport）

```
POST /api/payrollCalculation/payrollCollect/confirmImport
{
  "payrollSalaryPackageId": 2501,
  "payrollResultFilesUrls": ["..."],
  "excelDistrictDataMap": { "SPP202611110071": "[{...前端解析出的单元格 map...}]" },
  "countDataMap": { "SPP202611110071": [{ "settlementCode": "SEP20261111000168",
      "totalEmployerCostSc": 1213, "totalServiceFeeSc": 0, "currentPayableSc": 1213,
      "totalInvoiceAmount": 1213, "...": "..." }] },
  "payrollPayslipMatchList": [], "bankFilesUrls": [], "otherFilesUrls": []
}
```

| 要点 | 说明 |
| --- | --- |
| `excelDistrictDataMap` | 前端解析 Excel 得到的单元格 map（`{id,item:{指标:{v,t,f,fc}}}`），JSON 字符串形式提交 |
| `countDataMap` | 汇总行：`settlementCode` / `totalEmployerCostSc`（雇主总成本） / `totalInvoiceAmount`（发票金额）等 |
| 传空数据 | 返回「保存失败[区域结算包确认上传失败]」，**纯 Excel 驱动做不了，需框架 `payrollconfirm` 动作** ✅实测 |
| 成功后 | 结算包 tag 2 → 5（待财务审核）；薪资包 `payroll_status=2` ✅实测 |

## 4. 结算包审批（区域侧）

```
GET /api/center/gsrSettlementDistrict/{settlementDistrictId}/financialReviewCompleted
    ?operationItems=reCheck
    &settlementDistrictPackageId=13474
    &settlementDistrictPackageTag=5
    &headline=Lucas专用供应商 - France - 2026-11
    &reason=自动化测试通过
```
📄整理：区域侧把结算包「财务复核完成」推进到下一状态；`headline` 需与页面标题一致，`reason` 会写进审批意见。

## 5. 鉴权与权限

| 项 | 说明 |
| --- | --- |
| 权限码 | `center:payrollSalaryPackage:list` / `add` / `edit` / `query` / `remove` ✅实测 |
| 110106 排查顺序 | ① 换 `.env` 的 `ACCESS_TOKEN_ADMIN`（浏览器登录态，权限最完整）② 确认 token 未过期（约 2 小时）③ 新扫码会话可能缺权限，不要用它 |
| 错误 token | 返回 `{"code":500,"msg":"Internal Server Error"}` 而不是 401 —— 属健壮性缺陷 ⚠️ |

## 6. 框架里已封装的部分

| 能力 | 位置 |
| --- | --- |
| 按 ID 查询（含筛选、断言） | `api/common/payroll_package.py`：`query_salary_packages` / `get_salary_package` / `require_salary_package` / `package_variables` |
| Excel 动作 `pkgquery` | `api/common/executor.py`：查询后回填 `pkg_id` / `pkg_code` / `pkg_status` 等变量，`validata` 写 `pkg_status=0` |
| 确认结算 `payrollconfirm` | 同上：自动拼 `excelDistrictDataMap` / `countDataMap` |
| 国家模板指标反查 | `api/common/payroll_util.py`：`resolve_cells_by_indicator` |
