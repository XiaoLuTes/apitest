## 三、调用关系图（谁控制谁）

```
IMPLICIT_WAIT(15s) ──→ page.set_default_timeout ──→ 所有元素操作兜底
                                                      （find_element / click / fill / 取值...）

WAIT_ELEMENT_APPEAR(120s) ──→ wait_for_element_appear 总闸门
TIME_FIND(3s)         ──→ 循环内单次探测（appear 和 value 两个方法共用）
REFRESH_TIME(15s)     ──→ appear 的页面刷新节奏

EXPLICIT_WAIT(30s)    ──→ wait_for_element_value 总闸门
REFRESH_INTERVAL(5s)  ──→ value 的页面刷新节奏
TIME_FIND(3s)         ──→ 循环内单次探测（同上）

DB_TIMEOUT(20s)       ──→ 数据库连接
SLOW_MO(100ms)        ──→ 浏览器操作延迟（调试）
TIME_STAMP            ──→ 命名时间戳
```

## 五、单位规律总结（判断标准）

**看超时值最终"交给谁"：**

```
① 交给 Playwright API（set_default_timeout / loc.wait_for / fill / click...）
   → 必须毫秒（Playwright 规定）
   → IMPLICIT_WAIT(15000)、TIME_FIND(3000) ✅

② 交给自己写的 while 循环（time.time() - start_time < x）
   → 必须秒（time.time() 返回的就是秒）
   → EXPLICIT_WAIT(30)、REFRESH_INTERVAL(5)、REFRESH_TIME(15)、WAIT_ELEMENT_APPEAR(120) ✅

③ 交给 pymysql（connect_timeout）
   → 必须秒（pymysql 规定）
   → DB_TIMEOUT(20) ✅
```

> **口诀：和 Playwright 打交道用毫秒，和 pymysql 打交道用秒，和自己写的 `time.time()` 循环打交道用秒。**

## 六、易混淆点核对

| 易错点 | 当前代码 | 结论 |
|--------|----------|------|
| `set_default_timeout` 传毫秒 | `IMPLICIT_WAIT=15000` 直接传 | ✅ 正确（15000ms = 15s） |
| `loc.wait_for(timeout=)` 传毫秒 | `TIME_FIND=3000` 直接传 | ✅ 正确（3000ms = 3s） |
| 自己循环比较用秒 | `EXPLICIT_WAIT=30` vs `time.time()` | ✅ 正确（30s） |
| pymysql 超时用秒 | `DB_TIMEOUT=20` → `connect_timeout` | ✅ 正确（20s） |

**当前 9 个时间相关配置全部核对正确，单位语义自洽。**
